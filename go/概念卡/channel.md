# channel

## 一句话
> Channel 的本质是一个**带同步语义的类型安全管道**。它的价值不在于"传数据"，而在于**以结构化的方式表达并发协作关系**。

## 代码
```go
ch := make(chan int) //声明与初始化
ch :=make(chan int, 3) //声明与初始化,指定容量为3

ch <- 42  // 将数字 42 发送到通道 ch 中
result := <-ch  // 从通道 ch 中接收数据，并赋值给 result

close(ch) //关闭通道

//判断通道是否关闭
val, ok := <-ch
if !ok {
    // 通道已关闭，且里面的存货都被取光了
}
```

## 核心要点
- 要点1：理解非缓存通道和缓冲通道

| **维度**         | **无缓冲通道 (Unbuffered)**                     | **有缓冲通道 (Buffered)**         |
| -------------- | ------------------------------------------ | ---------------------------- |
| **初始化**        | `make(chan int)`                           | `make(chan int, 3)` (指定容量为3) |
| **类比**         | **接力赛跑**：交接棒时，递棒人和接棒人必须同时在场。               | **快递柜**：快递员把件放入柜子就走，你下班后再去取。 |
| **阻塞机制 (发送方)** | 只要没有其他的 Goroutine 准备好接收，发送方就会一直**死等（阻塞）**。 | 只要缓冲没满，发送方就可以一直扔数据；满了才会阻塞。   |
| **阻塞机制 (接收方)** | 只要通道里没有数据，接收方就会一直**死等（阻塞）**。               | 只要通道里没有数据，接收方就会阻塞。           |

## 常见坑
- **永远只应该由发送方来关闭通道**。向已经关闭的通道发送数据，或者重复关闭通道，会直接导致程序崩溃 (Panic)。
